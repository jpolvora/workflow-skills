# Context — 0180-us-510 (sanctioned single-agent state bootstrap)

Companion to [`0180-us-510.spec.md`](0180-us-510.spec.md). Records the product choice behind the bootstrap contract so the plan does not re-litigate it.

## Feature Boundary

- **In:** one documented, idempotent, fail-closed entrypoint that creates the initial `{workflow-id}.state.md` + `{workflow-id}.state.json` pair for a run and registers the `{plansDir}/index.json` row, so a single agent driving Step 0-9 directly reaches the state footprint a dispatched orchestration run has from its first step.
- **Out:** everything downstream of the pair (step artifacts, telemetry boundaries, checkpoints, verification manifest), any state recovery for runs that already shipped without state (issue #506), and run identity for `ws-spec-to-pr-lite` / `ws-spec-multi`.
- **Boundary test:** if a change does not affect the creation, replay, or refusal behavior of the bootstrap invocation, it belongs to another spec.

## Implementation Decisions

1. **Chosen: a new operation on the existing state runtime** (`workflow_state.cjs`, reached through the `ws-spec-to-pr/scripts/update_state.cjs` pass-through). Why: that module already owns the operation allowlist (`:2506-2508`), the canonical pair writer `syncStateDualWrite` (`:583-600`), the index refresh `refreshPlansIndexForState` (`:1181-1194`), and the validator `validateSnapshot` (`:2312-2451`). Creation is the only missing verb, and the module is already declared the sanctioned state writer (`:2468`). Two shipped sibling mutators prove the composition end to end (`commit_g2_code.cjs:125-129`, `refresh_baseline.cjs:172-177`).
2. **Decided: explicit inputs instead of inference.** Workflow id, slug, branch, and baseline are required flags; the runtime does not infer them from HEAD or the directory name. Bootstrap step 5b/6 already resolves exactly these values (`setup.md:113`, `:169`), so the command receives resolved inputs and stays deterministic and testable.
3. **Decided: the idempotent window is precisely "revision 0, empty `completedSteps`, non-terminal `status`".** `revision` is bumped by every operation (`workflow_state.cjs:1631`), so that triple is the only state that means "bootstrapped and untouched". Everything else refuses without mutating.
4. **Decided: fail closed on a partial pair.** A lone member indicates an interrupted or foreign write; completing it silently would adopt a run this invocation did not create.
5. **Decided: no telemetry boundary is emitted for the bootstrap itself.** The append-only stream documents step execution, and a synthetic `dispatch`/`finish` pair would corrupt elapsed-time derivation (`protocols/state-hygiene.md:42-49`). Observability comes from the invocation result and the index row.

## Deferred Ideas

- **Orchestrator-owned inline bootstrap** (prose that materializes the pair through the host `write-state` alias, expanded in `setup.md` step 5): rejected as the sanctioned path because it duplicates the pair writer, the index refresh, and the validator in prose, and it keeps the "hand-editing is unsupported" contradiction alive. Worth revisiting only if the runtime cannot expose a new operation.
- **The issue's alternative: a sanctioned state-less run mode** (own status marker plus a compensating evidence checklist). Not rejected on merit — it is a different product decision (accept no state, or create state). If it is ever adopted, it must be a second spec with its own status surface, and the bootstrap contract here still stands for runs that do want state.
- **A prompt-style bootstrap that scaffolds run identity only** (workflow id plus slug, no baseline and no branch): rejected for now because `validateSnapshot` and the plans-index row need the full identity, and a partial record would be a second unsanctioned shape.
- **Backfill of historical plan directories**: left to `validate_state.cjs rebuild-index`, which only catalogs existing pairs.
