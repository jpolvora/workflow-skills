# Context — us-511 (`fetch_threads.cjs` should fall back to `gh auth token`)

Companion to [`0181-us-511.spec.md`](0181-us-511.spec.md). Records the boundary of the change and the implementation choices that have two or more valid options. The spec pins observable behavior only; this file records where the code shape is still open.

## Feature Boundary

**In scope**

- Token resolution and its failure message in the canonical `.agents/skills/ws-spec-provider-github/scripts/fetch_threads.cjs`.
- Parity of `.agents/skills/ws-fix-pr/scripts/fetch_threads.cjs` with the canonical script, satisfied by keeping the forwarding shim contract intact (AC9, AC10).
- Documentation parity for the precedence chain: the provider `validate-auth` procedure (`ws-spec-provider-github/INTENTS.md:13`), plus the two `ws-fix-pr` surfaces (`scripts/COOPERATIVE_FIX.md:197`, `README.md:28`).
- A network-free test for the resolution order, the fallback, and the failure path.

**Out of scope**

- The other two implementations of the same lookup: `ws-spec-provider-github/scripts/resolve_thread.cjs:67-86` and `ws-shared/runtime/scripts/ingest_visual_attachments.cjs:240-251`. They already implement the fallback; whether they migrate to a shared helper is Decision 1.
- Azure DevOps credential resolution, the GraphQL query, thread filtering, and the `--json` payload shape.
- Any credential cache, keyring integration inside the script, or GitHub App / device-flow authentication.
- The pre-existing `loadDotEnv()` behavior that lets a `.env` entry overwrite an exported variable.

## Implementation Decisions

### Decision 1 — Where the fallback lives (open)

The defect is one missing link in one function, and the same lookup already exists three times in this package.

| Option | Shape | Advantages | Costs |
|--------|-------|------------|-------|
| **A. Inline in `fetch_threads.cjs`** (recommended) | Add ~10 lines to the existing `resolveToken()`, mirroring `resolve_thread.cjs:67-86` | Smallest diff; consistent with the established precedent in the same skill; no cross-skill or `ws-shared` blast radius; no install-scope or `HUB_SCRIPTS_DIR` interaction; reviewable in one screen | A third copy of the same env-then-CLI sequence; a future chain change must touch three files |
| **B. Extract one shared helper** | New `.cjs` under `ws-shared/runtime/scripts/`, adopted by `fetch_threads.cjs`, `resolve_thread.cjs`, and `ingest_visual_attachments.cjs` | Single source of truth for the chain; the fallback cannot drift between call sites again | Widens the change to three call sites and two skills; `ws-shared` resolution differs per install scope (project-local vs global vs packaged) and `fetch_threads.cjs` already carries a `HUB_SCRIPTS_DIR` candidate chain (`:11-38`); more surface to re-verify, and a `ws-shared` runtime addition carries its own integrity and parity obligations |

The spec is written to pass under either option: AC1–AC8 and AC12 describe behavior at the `<PR>` command surface, not the code shape. Option A is recommended because it fixes the reported defect with the smallest verified blast radius, and the duplication is already the package's established pattern; Option B is the better answer only if the maintainer wants one chain definition, which is a follow-up refactor rather than part of this defect.

### Decision 2 — Carrier for the AC12 source diagnostic (open)

AC12 requires an observable, non-secret signal naming the selected token source, because the precedence order cannot otherwise be verified without reaching the network.

- **One-line note on the standard error stream** — no payload change; invisible to `--json` consumers; simplest.
- **A `tokenSource` key in the `--json` payload** — machine-readable for tests and for `ws-fix-pr` diagnostics; adds a key to a payload that `test/test-provider-parity.js:490` and downstream callers already parse.

Either satisfies AC12 and AC14 (which freezes the existing keys but does not forbid an added one). Recommendation: the standard-error note, since the value is diagnostic and the JSON payload is consumed as data.

### Decision 3 — Test seam (open, low stakes)

The lookup is a module-private function in a script that calls `main()` on load, so a network-free test needs one of:

- **A `PATH` stub for `gh`** (recommended) — a fake CLI that prints a sentinel, exits non-zero, prints nothing, or records its invocation, combined with a scrubbed environment. Keeps the script's public surface unchanged and exercises the real `execSync` boundary, including the "stub never invoked" precedence assertion.
- **Exporting a resolution helper** (`module.exports`) so the test can call it directly — more direct assertions, but changes the script's module surface and requires guarding the `main()` call.

## Deferred Ideas

- **Unify all three token lookups** into one `ws-shared` helper once the chain stops changing (see Decision 1 Option B). Worth doing as a separate change with its own parity and integrity verification.
- **Fix the `.env` overwrite semantics** in `loadDotEnv()` so an exported variable is never replaced by a file value. Pre-existing behavior with a real footgun (a stale `AGENTIC_CODE_REVIEWERS_GITHUB_TOKEN` in `.env` beats an exported `GITHUB_TOKEN`), but out of scope here because it changes credential selection for every consumer.
- **`gh auth status` preflight** before the token read, to distinguish "CLI absent", "CLI present but unauthenticated", and "CLI authenticated but token unreadable" in the remediation message. Nice-to-have; AC5 already requires an actionable message for all three.
- **Timeout on the fallback subprocess.** `execSync` has no timeout in either existing implementation; a wedged `gh` invocation would hang the thread read. The precedent sets no timeout, so adding one here would break symmetry — candidates for a separate hardening change.
- **Extend the same fallback to the Azure DevOps provider** (`ADO_PAT` → `AZURE_DEVOPS_PAT`), if an equivalent CLI credential store is ever an accepted source there.
- **Assert the fallback in CI without `gh` installed.** Whether the package's test runner can stub `PATH` portably on every supported host is unverified; the test must degrade to a skip rather than a false red if the stub mechanism is unavailable.
