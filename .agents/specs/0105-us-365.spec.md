# Specification — ws-spec-to-pr orchestrator could dispatch and observer/watcher for errors during execution

## Description

Add an opt-in execution observer to the `ws-spec-to-pr` orchestrator that watches the workflow-skills execution pipeline itself (orchestrator and step subagents — not consumer product implementation) for errors and skill-instruction mistakes, logs them, and proposes fixes in the upstream repo.

System boundaries: orchestrator dispatch flow, workflow state file schema (agent transcript paths), `config.json` observer flag, one parallel read-only watcher subagent, a shared instruction module between the orchestrator and `ws-monitor`, and a watcher log plus fix-proposal report. Architecture touchpoints: `ws-spec-to-pr/SKILL.md` (+ dispatch table), `{workflow-id}.state.json` schema, `config.json` + schema + `ws-configure-project`, `ws-monitor` snapshot scripts and references, and the watcher log/report artifacts under the workflow directory. No consumer product paths, no provider or SCM contract changes.

Planned behavior: the state file records available agent transcript paths so `ws-monitor` (and the watcher) can follow execution; a new `autoStartObserver` config key (default `false`) gates a single parallel watcher subagent that reports state/execution and flags errors or bugs in skill instructions; the watcher shares its instruction source with `ws-monitor` instead of duplicating it.

## Acceptance Criteria

- AC1: Workflow state files record available agent transcript paths (explicit absent marker when unavailable), readable by `ws-monitor` — verified by a state-schema test with present and absent transcripts.
- AC2: `autoStartObserver` defaults to off (omitted or `false` means zero watcher dispatches) and explicit `true` enables the watcher — verified by a config-resolution test for omitted/false/true.
- AC3: When enabled, the orchestrator dispatches at most one parallel watcher subagent per run that reports state/execution and skill-instruction errors — verified by a dispatch-count test on an enabled run.
- AC4: The watcher is strictly read-only (no product-file edits, no state-file writes, no commits or PRs) — verified by a tree-hash immutability test over a watched run.
- AC5: Watcher findings are logged with error/bug classification plus fix proposals scoped to the upstream repo — verified by reading a sample log/report with classified entries and proposals.
- AC6: Orchestrator and `ws-monitor` share one instruction source for observation semantics (no duplicated drift) — verified by both referencing the same shared module or reference file.

## Notes

- "age transcription paths" is read as agent transcript paths (transcript/session locations the monitor already discovers); the plan confirms this reading against the `ws-monitor` adapter table.
- Watcher parallelism is bounded at one per run; the watcher never blocks step advancement and its absence (default off) changes no current behavior.
- Fix proposals are reports scoped to the upstream package; auto-committing, auto-filing, or auto-merging fixes is not part of this spec.
- Watcher scope is the harness execution only — consumer product files are never observed for content nor touched.

## Validation & Observation Notes

### Telemetry & Observable Signals

- State-file transcript-path fields (present paths vs explicit absent marker) asserted by a schema test.
- Watcher dispatch count: 0 on default-off runs, at most 1 on enabled runs.
- Watcher log/report artifact paths under the workflow directory with classified entries.
- Config resolution of `autoStartObserver` for omitted/false/true.

### Negative & Failing Test Scenarios

- Default-off run dispatches zero watchers (expected: dispatch count 0; fail if any watcher is spawned).
- Watcher attempt to edit a product file or write state fails closed (expected: immutability test red before the guard, green after).
- Transcript paths unavailable: state carries the absent marker and monitoring continues (expected: no crash, marker asserted).
- Watcher scoped to harness paths only: consumer product tree unchanged (expected: consumer tree hash identical before and after a watched run).
