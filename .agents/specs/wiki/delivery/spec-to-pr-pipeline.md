# Spec-to-PR Delivery Pipeline (`delivery`)

> Provenance: `.agents/skills/ws-spec-to-pr/SKILL.md`, `.agents/skills/ws-spec-to-pr-lite/SKILL.md`, `.agents/skills/ws-shared/runtime/scripts/workflow_state.cjs`, `.agents/skills/ws-spec-to-pr/scripts/step_coordinator.cjs`, living synthesis of specs 0006, 0016, 0021–0024, 0029, 0035, 0043, 0047, 0054, 0062, 0068, 0073–0074, 0082, 0084, 0089, 0090, 0092, 0094, 0095, 0097-us-354, 0099-us-352, 0101-us-355, 0105-us-365, 0117-us-386, 0118-us-393, 0120-us-388, 0121-us-395.

## Feature

The Spec-to-PR delivery pipeline turns an approved `*.spec.md` contract into a merged pull request through two orchestrators that share one project hub and one state contract. The standard orchestrator (`ws-spec-to-pr`) runs steps 0 through 9: spec registration, plan authoring, plan interview, DAG task breakdown, implementation, verify scoring, adversarial code review, testing, close, ship, and fix-PR convergence. The lite orchestrator (`ws-spec-to-pr-lite`) compresses the same guarantees into steps 0 through 5 for work that passes `ws-classify-complexity` thresholds. `ws-spec-multi` classifies each queued spec and dispatches exactly one pipeline at a time with isolated `workflowType` and no cross-resume between standard and lite. Outside Spec-to-PR, `ws-task-lifecycle` covers prompt-driven work through Intake → Implementation → Completion without creating a plan tree.

## How it works

A run begins at bootstrap with an explicit feature-branch strategy: create `feat/{slug}` from HEAD or base, or stay on the current branch. Standard Steps 1 through 3 always execute even in `autoMode`; `autoMode` automates only gate index 0, and Step 4 dispatch fails closed when plan artifacts are missing. Step 5 (`ws-plan-verify`) advances only when the derived score from `ac-ledger.json` reaches `defaults.minVerifyScore` (default 9). Uncovered negative scenarios cap the score at 8, and critical stack-invariant violations cap below the bar and force `scoreAndRefine` back into implementation.

Product files commit before review, never plan directories or secrets. After Step 5 reaches the verify bar, only `files_touched` paths stage into a product commit. Step 6 (`ws-code-review`) inspects the committed `base...HEAD` diff and STOPs when workflow files remain uncommitted. Review fixes get a separate product commit before testing or close. Implementation closes at Step 8 with `status: completed` and `shipStatus: pending` while MEMORY, changelog, and optional delivery artifacts persist; `ws-ship-pr` in `workflowMode` only pushes and opens the PR after close.

Shipping carries an optional non-blocking preview dry-run gate that observes the final pushed tree. Step 4b in `ws-ship-pr` reuses `preview.dryRunCommand` verbatim from the consumer repo root immediately after the Step 4 commit and push and before any Step 5 provider authentication or PR creation, recording its summary on the Prepare-to-PR board. The gate runs only when Create PR will actually execute, stays identical across GitHub and Azure DevOps providers, skips with a recorded reason when `preview.previewBeforeShip` is explicit `false` or the command is empty, and never blocks ship, merge, or handoff when findings or a non-zero exit appear. Single-session CLI-harness runs bind host capabilities once at bootstrap, run routine shell recipes quietly with non-interactive subject flags under a declared no-approval posture while keeping every step-boundary `user-gate`, and let `ws-ship-pr` auto-resolve head, base, remote, provider, commit title, stage set, and consumer prepare obligations before asking about genuine ambiguity only. Created pull requests still carry a GitHub auto-close keyword. `ensure_pr_closer.cjs` guarantees the PR body holds `Closes #N` for a numeric tracker id, leaves a body that already closes the issue alone, and skips local specs with a null id and non-GitHub providers without writing. GitHub honors that keyword only when the pull request base is the repository default branch. After a merge with zero active review threads, ship and in-session fix-PR convergence dispatch the `close-issue` intent so the linked work item reaches CLOSED on any base. `comment-issue` (alias `close-loop`) stays a comment and does not change tracker state. A local spec or a null id skips `close-issue` with exit 0, and a dry-run prints the planned close without calling the host.

Step skills no longer restate shared contracts. `gates.md` owns the gate tables and the minVerifyScore and scoreAndRefine rules, `PROTOCOLS.md` and `STEP-DISPATCH.md` own handoff and dispatch boilerplate, `tools.md` owns the `commit-code` G2 hunk-separation algorithm and the subagent model-role chain, `config-resolution.md` owns start-of-step banners, and `artifact-cleanup.md` owns the Step 8 combined gate plus Phase A cleanup. Callers keep a one- or two-line Contract pointer plus their own blast-radius delta, and standalone or lite invocations still carry skill-local guardrails instead of relying on dispatch injection.

Skill-owned blast-radius guardrails are explicit: `ws-implement-tasks` stages only `files_touched` and never runs `git add`, `commit`, or `push`; `ws-plan-verify` requires a Shell-capable session, refuses question-only read-only sessions, and never edits product files; `ws-plan-interview` lets a `force_interview: true` MEMORY conflict override soft-skip; `ws-plan-write` never touches git and always plans Section 6 stack-invariant verification; `ws-testing` never edits product or test sources and treats `skipQualityGates` as a gate-only bypass; and `ws-plan-to-tasks` writes no git or state files and invents no stubs.

Model selection supports a per-run preset override: `preset=<name>` (aliases `--preset=<name>`, `--preset <name>`) on the `ws-spec-to-pr` or `ws-spec-to-pr-lite` invocation replaces `defaults.modelsPreset` for that run only, so one execution can target `muse-spark`, `cursor`, `cheap`, or a custom bundle without editing project config. Unknown preset names log a warning in telemetry and the Init banner and fall back to the configured preset without halting. The resolved preset persists as `modelsPreset` in `{workflow-id}.state.json` and the `.state.md` frontmatter, and resume retains it without re-passing the flag; the Step 3 Init banner shows the value and whether it came from the override or `config.json`. The orchestrator session itself always stays on `currentModel`; the override governs subagent dispatch and phase resolution, while `stepModels` entries still beat preset values.

Fix-PR batches always plan on the reviewer model (`fixPrPlan` → `reviewerModel`) and execute on the fix model (`fixPrExec` → `executionModel`). `ws-goal-fix-pr` runs as an orchestrator: the skill session owns the wait/fetch convergence loop inline (initialize, convergence check, heartbeat wait, re-check, pre-merge gate, final report) and never authors plan gates or product fixes itself when dispatch is available, while every Act round batch runs in a freshly dispatched worker through the portable `dispatch-agent` alias. Each batch worker runs one ordered `fixPrPlan` → `fixPrExec` pair with the gate completed before any product or remote mutation, resolves its models through the same `stepModels` → preset role → top-level role → session-model chain as Step 9 (never numeric `"9"`), and emits ordered dispatch telemetry with actual versus configured models. Hosts with no bound subagent tool fall back to documented Tier 3 inline-isolated execution with identical gate and learning contracts. The `resolveReviewThread` mutation runs only after reply and commit verification. Hermes rules require a prior-work sweep, whole-class fixes or recorded exemptions, and sabotage or CI-triage hygiene before resolving threads. Fix-PR also starts from a dirty worktree by design: outer preflight snapshots `preExistingDirty` (tracked modifications, staged leftovers, untracked paths) and keeps operator-owned local harness helpers on disk for the whole batch, while whole-tree `git stash` before or after the batch is forbidden. Repository sync fetches first and intersects `HEAD..FETCH_HEAD` with `preExistingDirty`, pulling only when the intersection is empty and STOPping with the overlapping paths otherwise, and the batch commit stages only surgical fix paths plus recorded proactive same-class hits. When `defaults.enableDag` is false (the default), Step 4 tasks dispatch sequentially; when true, at most three parallel subagents may run. Cooperative session leases are retired; parallel work uses git worktrees instead of lease files. Standard dispatch through `build_dispatch_context.cjs` inlines the enhancing `## Subagent contract` sections from `ws-senior-developer`, `ws-tdah`, and `ws-self-learning` (the retired `ws-karpathy-guidelines` contract is consolidated into `ws-senior-developer`), capping each section at 40 lines plus a MEMORY slice.

Terminal close is contractual across single runs and batch queues. A run whose steps are all terminal still writes an explicit terminal `status` with `endedAt` instead of lingering as `active`, and the close step refuses to complete while any step reports failure. A batch child that finishes correctly propagates that outcome to its parent queue row so the parent `updatedAt` advances and the row leaves `in_progress`, batch ship updates transition existing queue rows instead of appending duplicate `pending` rows beside `shipped` rows, superseded batch runs retire atomically as a single canonical Markdown write with full-precision timestamps and deterministic newer-run ordering for lineage ties, and only the active run retires while stale rows stay untouched. Queue mutations are keyed by spec identity so the same item can never gain a second concurrent row and cause double processing.

Completion optionally continues into UI evidence collection. Two boolean switches with one folder setting gate a single opt-in post-completion proof-of-work step that runs after PR creation or fix-PR convergence while `status` is already `completed`. The workflow asks once through `user-gate` whether to start the evidence collector, and automatic collection starts it without asking when both switches are enabled. The collector writes numbered screenshots plus one Markdown evidence report per user story under the configured folder and never commits that folder unless separately asked, and cancellation plus slug sanitization keep the terminal transitions safe.

Step-level baton runs spread one run across CLI processes on the same machine and repository. `defaults.stepRunners` maps step numbers to opaque runner ids and `defaults.runners` binds each id to a command template with `{prompt}`, `{cwd}`, `{slug}`, and `{step}` substitutions plus a timeout and environment allowlist; unknown steps, runner ids, or empty commands fail fast before Step 0, and unmapped steps keep single-host dispatch. The state file carries a `baton` record (`holder`, `step`, `claimedAt`, `leaseUntil`, `revision`) as the sole turn signal: a claim succeeds only on matching revision with no live lease, `finish` releases exactly once while advancing `currentStep`, expired leases become re-claimable with logged holder, step, and attempt count, and `maxAttempts` (default 2) consecutive expiries move the workflow to `blocked`. The deterministic `step_coordinator.cjs` (plain Node, no LLM) owns the run loop — claim, spawn the worker one-shot with sparse pointers plus a baton envelope, await exit, verify advancement and artifacts — and is the only polling party (default 30s, range 5–300s). Gates surface at the coordinator as pause-and-prompt (index 0 in `autoMode`); worker gate output is a protocol violation. Every claim, release, expiry, spawn, and exit appends `baton_*` / `runner_*` telemetry, `ws-monitor` snapshots show holder and lease read-only, and an enabled spec-memo integration mirrors released handoff summaries into the vault payload shape. Out of scope by design: IPC between runners, multi-machine orchestration, CLI provisioning, and gate-menu changes.

## Backend

State lives in a single `{workflow-id}.state.json` SoT with `handoffs`, `acLedger`, and `shipStatus`, plus a rendered `.state.md` companion and append-only `telemetry.jsonl`. Shared helpers `workflow_state.cjs` and `validate_state.cjs --pre-advance N` enforce the same contracts across standard and lite. Configuration keys that govern delivery include `defaults.minVerifyScore`, `defaults.enableDag`, `defaults.testingModel`, `defaults.deliveryCommitArtifacts` (refined plan on by default, everything else opt-in), `defaults.modelsPreset` with `modelPresets` and `stepModels` (substep role beats numeric step beats preset beats phase key beats `current`, including the `muse-spark` preset where every role resolves to the session model), the invocation-level `preset=` override persisted as state `modelsPreset` (`workflow-state.schema.json`, `workflow_state.cjs --preset` on dispatch and finish), the fix-PR roles `fixPrPlan` / `fixPrExec`, the baton run config `defaults.stepRunners` / `defaults.runners` / `defaults.stepBaton` (`pollIntervalSeconds` 5–300 default 30, `maxAttempts` default 2), and `preview.previewBeforeShip` with `preview.dryRunCommand` for the optional Step 4b dry-run gate that defaults to enabled and is disabled only by explicit `false`.

Branch discipline keeps `state.branch` as the PR head while `project.workingBranch` and the base branch never rewrite. Protected branches (`main`, `master`, `develop`) deny-list from cleanup, and Phase A git cleanup runs only at terminal `shipStatus`. Timesheet proof comes from `ws-activity-report`, which bills Human Total inclusive of agent supervision (Human ≥ Agent Running when agent time is positive) and treats idle or AFK gaps over 30 minutes as non-billable.

Worker turns are structurally hardened against premature endings that used to force full re-dispatches. Every dispatch path carries a turn rule stating that the first response must contain both the VerboseMode preview and at least two tool calls, and a response with zero tool calls ends the turn as failed delivery rather than resolving `completed`. A turn that ends with required step artifacts unwritten emits an explicit non-success signal so the parent fails fast instead of waiting on artifact timeouts. Parent liveness probing of long workers is read-only by contract: no mid-batch ping may inject a terminal message into a working turn, and a continuation worker that recovers an interrupted turn reuses the intact worktree partial progress instead of rebuilding context from scratch.

Step completion is contractual, not decorative. A step marked `completed` has its mandatory artifact on disk, and a completed mutating step reports a non-empty `filesTouched` handoff in telemetry unless the step genuinely modified nothing and declares the no-op explicitly. `ws-monitor` flags both violation classes in its read-only snapshots, with historical runs classified so old batches do not flood the monitor.

The orchestrator carries an opt-in execution observer for the pipeline itself. Workflow state records available agent transcript paths so observation can follow execution, and the `autoStartObserver` config key (default `false`) gates a single parallel watcher subagent per run that reports state and flags errors or mistakes in skill instructions. The watcher is strictly read-only and shares its instruction source with `ws-monitor` instead of duplicating observation semantics, and its findings land in the workflow directory as classified errors with fix proposals scoped to the upstream repo.

Fix-loop execution posture is configurable with one shared key. `ws-goal-fix-pr.useSubAgents` absent or `false` runs the whole fix-PR loop inline in the current turn, the historical fast path, with zero subagent dispatches; explicit `true` restores per-iteration subagent dispatch with identical behavior. The single key gates every subagent-dispatch loop iteration across the fix path that spans `ws-fix-pr`, `ws-goal-fix-pr`, and the pre-ship loop inside `ws-ship-pr`, and schema, GUI config editor, and docs change atomically with the runtime gate.

Standard children persist the same state contract as single runs. Every dispatched child writes its own machine `{workflow-id}.state.json` plus the rendered `.state.md` companion, per-step artifacts, and `telemetry.jsonl` under its `{plansDir}/{slug}/` directory so the batch stays observable and resumable with delivery evidence intact. The child-exit guard fails closed on unparseable state, missing identity, slug mismatch, or unsafe queue slugs, and it treats the queue transition as an executable step rather than a silent alias. The monitor computes a real expected-artifact set for multi-spec children instead of an empty list, so absent child state now surfaces as a finding through `record_child_outcome.cjs`, `verify_child_artifacts.cjs`, and `retire_superseded_run.cjs`.
