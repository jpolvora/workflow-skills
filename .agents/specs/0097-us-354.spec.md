# Specification — Worker turns ending prematurely mid-step force orch re-dispatch (preview no-op + ping termination)

## Description

Harden the orchestrator-to-worker dispatch contract so a dispatched worker turn cannot end prematurely and silently force a full re-dispatch. Two observed failure modes from run `step-baton-multi-agent-runs-20260918T232508Z` (PR #350) must be closed harness-side:

1. **Preview-only no-op:** a `ws-plan-verify` Step 5 worker printed the VerboseMode `Starting step 5 (Verify):` preview, then ended its turn with 1 model turn and 0 tool calls — no spec reads, no tests, no `step-05-*.plan.report.md`. The parent detected the missing artifact and re-dispatched (~15 min wasted).
2. **Ping-as-terminal-message:** a batch-3 fix worker doing real work (46 model turns) received a parent queue-mode status ping (`baton-batch3-ping`); its next message — a status reply — became its terminal output (`terminal` + `completed`), leaving fixes uncommitted with no round report. A continuation worker recovered from the intact worktree.

System boundaries: the harness cannot change model-host turn-termination behavior; all fixes are prompt-contract, detection-signal, and recovery-path changes on the harness side. Architecture touchpoints: dispatch prompt builders (`build_dispatch_context.cjs` and STEP-DISPATCH addenda), `gates.md` verbose-preview rule, `step_coordinator.cjs` (baton runs), worker turn protocol (step-output DONE envelope), step telemetry JSONL schema, and parent liveness-probe behavior. Dependencies: shared worker-turn rule text used by standard dispatch, baton coordinator, and inline-isolated execution; telemetry consumers (`ws-monitor`).

## Acceptance Criteria

- AC1: Every dispatch path (standard `dispatch-agent`, step-baton coordinator, inline-isolated) carries a structural turn rule stating the first response must contain BOTH the verbose preview AND at least 2 tool calls, and a response with zero tool calls ends the turn as failed delivery — verified by grepping the dispatch prompt sources for the rule text.
- AC2: A worker turn ending with zero tool calls emits an explicit non-success signal (failed step-output envelope and/or telemetry event), so the parent fails fast without waiting on artifact timeouts — verified by a regression test simulating a preview-only turn.
- AC3: A worker turn ending with required step artifacts unwritten (e.g. `step-05-*.plan.report.md`, round report) emits an explicit non-success signal instead of resolving `completed` — verified by a regression test asserting the artifact-presence check runs before finish.
- AC4: Parent liveness probing of long workers cannot terminate the probed turn: either a read-only status poll that injects no terminal message, or a documented never-ping-mid-batch contract plus a non-messaging progress signal — verified by code showing no mid-batch ping path remains in the parent dispatch loop.
- AC5: A continuation worker recovering an interrupted turn reuses the intact worktree partial progress (verify, commit, resolve, push, report) instead of rebuilding context from scratch — verified by an end-to-end or fixture test of the resume path.
- AC6: Regression coverage pins each failure mode (preview-only no-op, ping-mid-batch, unwritten-artifact completion) so a future prompt edit that drops the guard fails the suite — verified by `npm run test` green with the new fixtures.

# Worker turns ending prematurely mid-step force orch re-dispatch (preview no-op + ping termination)

Related: #353 (loop-session wedge + resume no-op). This issue covers two more premature-turn failures in the same run that forced the orchestrator to cancel/re-dispatch mid-step work.

## Instance 1 — Step 5 verify dispatched, did nothing (preview-only no-op)

- Dispatched `ws-plan-verify` (Step 5) with full context pointers + VerboseMode addendum.
- Child `01a0b6f5-ced1-73a1-82c8-36a43f5ef7bb` (`subagent/01a0b6f5-cee0-7122-b787-37946ebf97e9/session.jsonl`): **44 log lines, 1 model turn, 0 tool calls**. Entire output was the `Starting step 5 (Verify):` preview; no spec/ledger reads, no tests, no `step-05-*.plan.report.md`.
- Orchestrator detected the missing report artifact and re-dispatched a fresh worker with an explicit structural rule ("complete verification AND write the report in this turn; preview without work is failed delivery").
- Retry child `01a0b6f6-9db2-7fa1-aedd-294d622dd9b4` ran ~15 min and scored 9/10.
- Cost: one wasted dispatch + ~15 min of wall time before the retry even started producing (detection was artifact-based, not signaled).

## Instance 2 — batch-3 fix worker terminated by a parent status ping

- Batch-3 worker `01a0b75f-6d3e-7650-bd98-881d10303b37` was mid-batch after ~20 min (46 model turns of real work: 30 bash, 31 reads, 13 edits; fixes + tests implemented, full suite mid-verification, no push/report yet).
- Parent sent a queue-mode status ping (`baton-batch3-ping`, asking for activity + ETA).
- Ping arrived at worker log seq 1817 of 1835 (`subagent/01a0b75f-6d53-7a22-9069-866b88155afa/session.jsonl`). The worker's **next message — a status reply ("Remaining: … ETA ~10 min. No blocker.") — became its terminal output**: `terminal` + `completed` follow immediately, with no further tool calls. No push, no round report, fixes left uncommitted.
- A continuation worker (`01a0b773-a160-7610-913a-70bae9df7e58`) verified, committed `c4b66bfd`, resolved, pushed, and reported from the intact worktree.
- Cost: one extra dispatch; parent now avoids pinging workers mid-batch entirely (batches 4–7 ran unpinged with no recurrence).

## Impact

- Every premature turn costs a full re-dispatch (context rebuild + repeated reads) and, worse, is silent: the parent only notices via missing artifacts or elapsed time, never via an explicit failure signal.
- Pings — the only liveness probe the parent has — can themselves kill the turn they probe, removing the probe as an option.
- Same run also hit the loop-session wedge + resume no-op (#353), so 4 of ~15 dispatches in one run ended prematurely in three different ways.

## Suspected causes (to investigate)

1. **Preview-then-yield:** the VerboseMode "print preview before any tool call" instruction keeps inducing turn end right after the preview (5th instance counting #353), even with explicit structural mandates to continue.
2. **Ping-as-final-message:** a queued status message delivered late in a long worker turn appears to be treated as a prompt to *respond and finish* rather than *acknowledge and continue*. Possibly the model interprets any parent message as a new terminal request, or the runtime closes the turn after the next assistant message post-interrupt.
3. **No failure signal:** both cases resolved as `completed` (or ready-with-text), so the parent cannot distinguish "done" from "gave up" without artifact checks.

## Follow-ups

- [ ] Harden the VerboseMode addendum (shared with #353): mandate tool calls in the same response; never end the turn after the preview.
- [ ] Define a safe liveness probe for long workers that cannot terminate the turn (read-only status poll), or document "never ping mid-batch" as the contract and give parents a non-messaging progress signal instead.
- [ ] Emit an explicit non-success signal when a worker ends with zero tool calls or with required artifacts unwritten, so parents can fail fast instead of waiting out full timeouts.
- [ ] Consider resuming (not re-dispatching) interrupted workers when the worktree already holds their partial progress.

### Design Intent

- The VerboseMode `Starting step N` preview is an intentional contract (operator visibility); ending the turn right after the preview is an accidental gap — the prompt orders preview-before-tools but never forbids yielding after the preview, and the OUTPUT FORMAT example reads like a valid final message. Fix is prompt-structural, not a behavior change.
- Queue-mode status pings were the parent's intended liveness probe; their terminal effect on long worker turns is accidental (model treats a late parent message as a new terminal request, or the runtime closes the turn after the next assistant message post-interrupt). Fix may remove or restrict the probe, which is a deliberate contract change owned by AC4.
- Greenfield new behavior (failure signals, probe contract) — no prior intentional constraint to preserve beyond the items above.
