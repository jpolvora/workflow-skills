# Specification — Revamp website visual and template with docs-style layout

## Description

Revamp the visual layout and HTML/CSS template of the project website (`docs/`, generated by `bin/build-site.js` from `AGENTS.md` + skills content) so pages read as a modern docs experience in the style-pattern of the referenced docs overview page: a persistent top header, a grouped left section navigation, a focused main article column, and a right on-this-page table of contents, collapsing gracefully on smaller viewports.

Technical scope and boundaries:

- Template and styling work belongs in the site generator (`bin/build-site.js` and its HTML template strings) plus the stylesheet (`docs/assets/css/style.css`). `docs/index.html` itself is build output and must be regenerated, not hand-edited.
- All existing site content, sections, anchors, SEO/meta tags, structured data, and `llms.txt` / `sitemap.xml` / `robots.txt` behavior are preserved; this is a visual/template change, not a content rewrite or information-architecture migration.
- The reference page is layout inspiration only. The implementation must be original HTML/CSS with no copied stylesheet, font files, images, logos, brand marks, or text lifted from the reference site.

## Acceptance Criteria

- AC1: The generated page implements a docs-style three-region layout (top header bar, grouped left section navigation, main article column, right on-this-page TOC) using original HTML/CSS in the generator template and stylesheet.
- AC2: Every content section and anchor present before the change still exists after the change with the same ids, and every internal anchor/nav link resolves to an existing target.
- AC3: The shipped `docs/index.html` is produced by running the site builder (`node bin/build-site.js`); no hand-edits to generated output are required and a clean rebuild reproduces the new layout deterministically.
- AC4: At desktop width all three regions are visible; at narrow widths the layout collapses (right TOC drops first, left nav becomes a toggleable overlay/drawer) with no horizontal page scroll at 360 px viewport width.
- AC5: Navigation is keyboard-operable with visible focus, the page keeps semantic landmarks (header, nav, main) plus a skip-to-content link, and body text meets WCAG AA contrast against its background.
- AC6: No new render-blocking third-party requests are added (no external font/CDN script/iframe required for layout); the existing single-bundle CSS approach is kept and cold page load does not regress observably.
- AC7: SEO and sharing metadata behavior is unchanged in effect (title, canonical, description, Open Graph/Twitter tags, JSON-LD blocks, `llms.txt`, `sitemap.xml`, `robots.txt`).
- AC8: The change ships zero assets copied from the reference site: no third-party stylesheet, font, image, logo, brand mark, or verbatim text from it; similarity stays at the layout-pattern level.

### Design Intent

- `docs/index.html` is generated output: `bin/build-site.js` states it regenerates `docs/index.html` from `AGENTS.md` + skills (version stamped from `package.json`), and the page links `assets/css/style.css`. The constraint that visual changes go through the generator template/CSS and are verified by rebuilding is intentional, so a direct hand-edit of `docs/index.html` would be overwritten by the next build. This spec therefore targets the template + stylesheet with `docs/` refreshed via rebuild.

## Notes

- Current page facts grounding this spec: single static page (`docs/index.html`, ~200 KB) with `data-theme="dark"`, one stylesheet (`assets/css/style.css`, ~89 KB), JSON-LD `SoftwareApplication` + `FAQPage` blocks, and sibling `docs/wiki/` output owned by `bin/build-wiki-site.js` (left untouched unless a shared template forces it).
- Suggested layout mapping: header (project name, version, key links) → left nav (grouped catalog sections mirroring page sections) → article (existing sections in existing order) → right TOC (per-section heading links); existing dark theme is kept.
- Memory folded in: integrity regeneration goes last before ship when hashed content changes; PowerShell JSON-quoting and byte-rewrite traps apply to later implementation/verification commands, not to this spec.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Copying the reference site's stylesheet, fonts, images, logos, or text verbatim | Would reuse third-party copyrighted expression; this spec requires an original implementation |
| Splitting the single page into multiple routed docs pages | Information-architecture migration, not requested; layout revamp only |
| Full-text search backend or faceted navigation | New runtime feature beyond a visual/template change |
| Rewriting page copy or reordering content sections | Content freeze keeps review focused on template/visuals |
| Wiki site (`docs/wiki/`, `bin/build-wiki-site.js`) restyle | Separate output owned by a different builder; only adjust if a genuinely shared template requires it |
| New light/dark theme toggle or brand redesign | Existing dark theme is kept; toggle work is a separate decision |

## Validation & Observation Notes

### Telemetry & Observable Signals

- `node bin/build-site.js --check` — builder/template self-check passes.
- `node bin/build-site.js` followed by `git status --porcelain docs/` — rebuild reproduces the new layout with only expected generated diffs.
- Anchor audit — every `href="#..."` in the built page matches an existing element `id` (report the exact command and failure count used at implementation time).
- `npm run test` — repo suite passes after the template change.
- Manual viewport pass at wide, tablet, and 360 px widths plus a keyboard-only nav pass (drawer open/close, focus visibility, skip link).

### Negative & Failing Test Scenarios

- Red: builder exits non-zero after a template edit (e.g. unclosed tag or missing section token) — page must not ship until `--check` passes.
- Red: anchor audit reports orphan `#` links after a section rename — build is rejected until ids/links agree.
- Red: 360 px viewport shows horizontal page scroll — collapse rules fail.
- Red: nav drawer cannot be opened/closed by keyboard or focus is invisible — accessibility AC fails.
- Red: any third-party stylesheet, font file, image, logo, or verbatim text from the reference site is detected in the diff — originality AC fails and the asset must be removed.
- Red: title, canonical, OG/Twitter, JSON-LD, `llms.txt`, sitemap, or robots behavior differs from baseline without intent — metadata AC fails.
