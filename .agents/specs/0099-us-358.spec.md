# Specification — Add AGENTS.md rule: check the skill dependency graph when editing a skill so callers and callees stay in sync

## Description

Skills in this harness call each other: the orchestrator dispatches step skills, and provider/utility skills share contracts (for example, spec-list and spec-index overlap on listing/tracking). Editing one skill contract (inputs, outputs, scripts, file conventions) without checking its dependents leaves the harness inconsistent.

Add a project `AGENTS.md` authoring rule requiring that when fixing, updating, or editing a skill, the agent consult the skill dependency graph (the `bin/skill-dependencies.json` manifest and package membership) to identify callers and callees, verify their contracts still hold against the change, and update them in the same change or record explicit follow-ups. The rule must also require regenerating integrity data and running the harness checks over the whole affected set.

System boundaries: documentation and authoring-process change only. Architecture touchpoints: root `AGENTS.md` (Harness change protocol / authoring guidance), `bin/skill-dependencies.json` (dependency graph source), integrity scripts (`npm run generate-integrity`, `npm run verify-integrity`), and harness gates (`ws-check-harness`, `test/test-harness-clean.js`). No runtime skill behavior changes beyond the new authoring obligation.

## Acceptance Criteria

- AC1: Root `AGENTS.md` contains an authoring rule stating that every skill edit must consult `bin/skill-dependencies.json` (callers and callees), verify dependent contracts, and either update them atomically or record explicit follow-ups — verified by grepping `AGENTS.md` for the rule text and manifest reference.
- AC2: The rule requires regenerating integrity data (`npm run generate-integrity` + `npm run verify-integrity`) and running the harness checks (`ws-check-harness` / `test/test-harness-clean.js`) over the whole affected skill set — verified by reading the rule text.
- AC3: A worked example is present (e.g. changing the spec-list skill triggers a check of the spec-index skill for matching updates) — verified by reading the rule section.
- AC4: `npm run verify-integrity` and `node test/test-harness-clean.js` pass after the docs change — verified by command exit 0.

- The existing `AGENTS.md` Harness change protocol already requires integrity regeneration and harness checks on skill changes; the missing piece is the explicit dependency-graph (callers/callees) check. ## Notes

- Keep the rule portable and host-neutral: reference the manifest path and integrity commands, not host product names.
- Place the rule in the existing Harness change protocol / authoring section so it ships with the current before-ship checklist, not as a parallel process.
- Stack is `node-skills-package` (docs + JSON manifest + Node scripts); no framework-specific stack invariants apply beyond running the Node harness checks.
