# Spec Context — us-506: workflow state bootstrap for `ws-spec-to-pr`

Companion to [`0176-us-506.spec.md`](0176-us-506.spec.md). Records the product choices the issue leaves open, the defaults this spec pins, and what is deliberately deferred. Read with the parent spec's Assumptions table; nothing here weakens an AC.

## Feature Boundary

**In scope (this spec).** The orchestrator-owned creation path for run state: one packaged bootstrap operation that writes `{workflow-id}.state.json` and the rendered `{workflow-id}.state.md` for a **new** run, keeps the `{plansDir}/index.json` row hash-coherent, and makes the Step 0 boundary a fail-closed precondition whose non-zero exit is an explicit `autoMode` hard stop. AC1-AC18 are the whole contract.

**Out of scope (other owners).**

- Visibility of a run directory that has step artifacts but no state file: assigned by the source issue to a separately filed companion observability issue. This spec fixes the state-ful path only.
- A sanctioned bootstrap for a non-orchestrator single agent: sibling issue #510. This spec must not absorb that angle; the operation defined here takes orchestrator run arguments (workflow id, slug, pipeline) and the registered `step-00` spec.
- Repair or migration of existing state files, and any legacy path alias or dual-default behavior (the package ships latest-layout behavior only).

**Boundary test.** A change belongs here only if it is required to create the first state pair, to keep that pair index-coherent, or to make the missing-state failure fail closed and stop an unattended run. Anything that reconstructs, repairs, or observes an already state-less run belongs to the other owners above.

## Implementation Decisions

Decision 1 — bootstrap surface (pinned: extend the sanctioned writer).

| Option | Consequence |
|--------|-------------|
| `update_state.cjs init` backed by `workflow_state.cjs` (**pinned**) | One writer for machine state, the recorded "sanctioned writer" invariant holds, the absent-state error can name exactly one remediation command, and both orchestrator wrappers inherit the operation with no new entry point. |
| A new sibling script (for example `bootstrap_state.cjs`) calling `workflow_state.cjs` exports | Cleaner separation, but creates a second state-writing entry point whose drift from the update path (index refresh, dual write, schema conformance) is exactly the class of defect recorded in `.ws/MEMORY.md` § `[2026-09-19] Every programmatic state writer must refresh the plans index row`. |

The issue's own wording ("for example `update_state.cjs init` backed by `workflow_state.cjs`") is the basis for the pinned option; the alternative stays documented because it is a legitimate design if the implementation prefers script-level separation with a hard shared-helper contract.

Decision 2 — re-bootstrap over an existing state (pinned: fail closed).

| Option | Consequence |
|--------|-------------|
| Non-zero exit, existing files untouched (**pinned**) | Protects run progress and resume identity. A resumed run loads state and skips bootstrap entirely, so the fail-closed path blocks nothing legitimate. |
| Idempotent no-op reporting "already initialized", exit 0 | Friendlier for scripts that always call the bootstrap before branching, but an exit-0 no-op makes a broken or truncated state look healthy, and `validateSnapshot` would still fail later with a less direct message. |
| Overwrite or reconcile the existing state | Rejected for this spec: destroys progress, and reconciliation needs rules (which fields win, how `revision` advances) that this issue does not define. Listed under Deferred Ideas. |

Decision 3 — identity and render source at bootstrap (pinned: arguments plus registered spec, ledger optional).

The issue says the `.state.md` should be rendered "from the spec/AC ledger". The pinned default renders from the run arguments plus the registered `step-00-{slug}.spec.md`, folding `ac-ledger.json` when it already exists but never requiring it. Rationale: keep the bootstrap order-tolerant relative to `ac_ledger.cjs init` (both are Step 0 artifacts per `STEP-DISPATCH.md:37`) and avoid a second source of truth, because the first update operation re-derives AC counts from the ledger anyway. The alternative (make the ledger a hard input) would couple two Step 0 artifacts in a fixed order for no contract benefit.

Decision 4 — where the Step 0 precondition is enforced (pinned: generalize the existing gate, not a new interlock).

`validate_state.cjs --pre-advance N` already fails closed when state is absent; only the `; HS-5` label is restricted to pre-advance 4 (`workflow_state.cjs:2654-2655`). The pinned choice generalizes the label to any standard pre-advance failure caused by absent state and documents the Step 0 to Step 1 boundary in the golden-path command list. A dedicated new "bootstrap check" script was considered and rejected: it would duplicate a gate that already exists and add a second place for the HS-5 wording to drift.

Decision 5 — enforcing the `autoMode` stop (pinned: contract and observable records).

No script can force an orchestrator to honor a non-zero exit. The pinned choice keeps the enforcement where the contract already lives (`gates.md:52` hard-stop list, `STEP-DISPATCH.md:19` no-edits/no-dispatch wording) and makes the bypass observable through the existing `gate-bypass | pre-advance` record, with `skipQualityGates` explicitly not waiving the bootstrap itself (AC11). A machine interlock was rejected as out of scope for this issue.

## Deferred Ideas

- **Explicit repair path.** A `--force` bootstrap that re-creates state for a run whose state file is corrupt or truncated, plus the reconciliation rules it needs (what survives from the old file, how `revision` and `completedSteps` are carried forward). Deferred: destructive by default, and the fail-closed default is safe until a real recovery need is reported.
- **Adopting a state-less in-flight run.** Reconstructing state (and derived telemetry) for a run that already advanced without state, so the run becomes resumable and auditable after the fact. Deferred to the companion observability work: inventing dispatch provenance and elapsed times would fabricate machine history that every downstream gate treats as derived fact.
- **Bootstrap precondition beyond Step 0.** Requiring a recorded bootstrap marker at every step boundary, not just Step 0 to Step 1. Deferred: the pre-advance gates for steps 4/6/7/8/9 already fail closed once state exists, so this adds cost without a new failure class.
- **A `state` diagnostic in the harness/doctor surface.** Reporting "run directory has step artifacts but no state" as a first-class finding rather than only as monitor output. Belongs to the companion observability issue.
- **Locking the create path.** Replacing the create-only guard with a real lock so two concurrent bootstraps interlock instead of one failing closed. Deferred: `atomicWrite` already prevents partial files, and a lock contract is a larger change than this issue requests.
