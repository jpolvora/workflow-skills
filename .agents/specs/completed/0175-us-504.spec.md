# Specification — check_workflows.cjs: findRepoRoot() mis-resolves repo root to ~/.agents when the global install dir is a git repo (19 false CRITICALs)

## Description

Fix `ws-check-workflows/scripts/check_workflows.cjs` repo-root and skills-dir resolution so a global-only install whose global install directory is itself a git repository no longer produces false CRITICAL findings.

System boundaries:

- Target script: `.agents/skills/ws-check-workflows/scripts/check_workflows.cjs` (`findRepoRoot()`, `resolveSkillsDir()`, `parseArgs()`).
- Reference pattern: `ws-check-harness` gate scripts (`check_harness_links.cjs`, `detect_install_mode.cjs`, `check_unique_runtime.cjs`) which accept `--repo-root <dir>` and `--repo-root=<dir>` forms.
- Install scope in scope: global-only install where the skills tree lives under `<globalRoot>/skills/ws-*` and `<globalRoot>` itself contains `.git`.
- The resolver must prefer the ancestor that actually contains the skills tree, accept an explicit `--repo-root` override, and never derive `SKILLS_DIR` as `<repoRoot>/.agents/skills` when the skills tree is already known from the script location.
- Local project installs (`.agents/skills` under a normal repo root) must keep passing unchanged.

## Acceptance Criteria

- AC1: When `check_workflows.cjs` runs from a global install where the global root contains `.git` and skill bodies live under `<globalRoot>/skills/ws-*`, the resolver shall report `PASS` with exit 0 instead of 19 false findings.
- AC2: If `findRepoRoot()` would otherwise return the install directory itself, then the resolver shall prefer the ancestor that contains the skills tree or fall back to an explicit override before probing `ws-*` paths.
- AC3: Where `--repo-root <dir>` is passed, the script shall use that directory as the repo root for all downstream probes, consistent with the `ws-check-harness` gates.
- AC4: The script shall accept both `--repo-root <dir>` and `--repo-root=<dir>` forms and the parsed value shall take effect for the run.
- AC5: When no marker matches, the script shall fall back to the invoking working directory or global-dir hint rather than an arbitrary ancestor index.
- AC6: The regression suite shall include a fixture where the script sits under a `.git`-rooted ancestor that also contains the skills tree, and the fixture shall assert zero false CRITICAL findings.

## Original Issue Context

## Summary

`ws-check-workflows/scripts/check_workflows.cjs` mis-resolves the repo root on a **global-only install when the global install directory (`~/.agents`) is itself a git repo**. It then looks for pipeline skills one level too deep (`~/.agents/.agents/skills/...`) and reports **19 findings (18 CRITICAL)** for files that all exist on disk. The same script, run from a copy outside that tree, reports `PASS` with **0 issues**.

Because the script has no `--repo-root` flag (unlike its `ws-check-harness` siblings) and ignores `cwd`, there is no CLI workaround other than copying the script elsewhere.

## Impact

- Any consumer whose global install lives in a version-controlled `~/.agents` gets a false **FAIL** from `/ws-check-workflows`.
- Misleading remediation advice ("Restore … from upstream repository") pushes users toward re-installing/overwriting healthy files.
- The skill's documented DoD ("exits 0") is unreachable on such installs, so the gate cannot be used as a real signal.

## Root cause

`scripts/check_workflows.cjs` (v0.5.39), lines 19–33:

```js
function findRepoRoot(startDir) {
  let curr = path.resolve(startDir);
  const roots = [curr];
  let p = curr;
  while (p !== path.dirname(p)) { p = path.dirname(p); roots.push(p); }
  for (const c of roots) {
    if (fs.existsSync(path.join(c, '.git')) || fs.existsSync(path.join(c, 'package.json')) || fs.existsSync(path.join(c, '.agents'))) return c;
  }
  return roots[Math.min(2, roots.length - 1)] || '/';
}

const REPO_ROOT = findRepoRoot(SCRIPT_DIR);   // SCRIPT_DIR = ...\.agents\skills\ws-check-workflows\scripts
```

Walking up from `SCRIPT_DIR`, the **first** ancestor matching `.git` is `C:\Users\jpolv\.agents` — the global install dir itself. So:

```
REPO_ROOT   = C:\Users\jpolv\.agents                      (wrong: should be C:\Users\jpolv)
configPath  = C:\Users\jpolv\.agents\.ws\config.json      (absent)
            → C:\Users\jpolv\.agents\.agents\skills\ws-shared\config.json  (absent)
token       = null
SKILLS_DIR  = C:\Users\jpolv\.agents\.agents\skills → absent → falls back to REPO_ROOT
```

`resolveSkillsDir()` (lines 35–50) then falls back to `repoRoot`, and every `ws-*` path is probed under `C:\Users\jpolv\.agents\ws-*` instead of `C:\Users\jpolv\.agents\skills\ws-*`.

This is precisely the class of bug fixed for other scripts in the 0.5.3x line (cf. #211, #494, #496, #498): scripts must not bind the repo root from their own location when the global install dir is the git root.

## Suggested fix

Either or both, mirroring the `ws-check-harness` gates:

1. **Prefer the ancestor that actually contains the skills tree.** Treat `...\.agents\skills` (i.e. an ancestor `c` where `path.join(c, '.agents', 'skills')` exists) as the repo root ahead of a plain `.git` match. Since `SCRIPT_DIR` already lives under `skills/ws-check-workflows/scripts`, resolve `SKILLS_DIR` first (walk up to the directory containing `ws-shared/` + the `ws-*` folders), then derive `REPO_ROOT` as its parent-minus-`.agents` when present.

2. **Add `--repo-root <dir>`** to `parseArgs()` (lines 578–589), matching `check_harness_links.cjs` (`else if (argv[index] === '--repo-root') repoRoot = argv[++index];`). The harness already calls its gates with `--repo-root {repoRoot}`, so `/ws-check-workflows` becomes invocable the same way from a global install.

3. Optionally fall back to `cwd` (or `WORKFLOW_SKILLS_GLOBAL_DIR`) rather than `roots[2]` when no marker matches.

## Workaround (users)

Run the script from a copy outside the `.agents` git tree (so `findRepoRoot` resolves to the directory containing `.agents`), as shown in "Proof" above.
