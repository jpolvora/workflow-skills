# Context — us-508 (`check_workflows.cjs` residual repo-root and parity-skip gap)

Companion to [`0178-us-508.spec.md`](0178-us-508.spec.md). Records the open product choices behind the pinned defaults. The spec is authoritative; this file explains what was decided, what was rejected, and why.

## Feature Boundary

In scope for the spec:

- `findRepoRoot()` outcome for an installation whose skills tree lives at `<root>/.agents/skills`, and the precedence between an explicit `--repo-root`, a consumer checkout at cwd, the global install root, and the no-marker fallback.
- Observability of that resolution (resolved root and provenance) in the `--json` payload.
- Reporting posture for the shared-vs-bin dependency parity check when its target cannot be resolved, and the write scope of `--report`.
- Regression coverage in `test/test-check-workflows-global-root.js` for the `<home>/.agents/skills` shape without a `.git` marker.

Out of this boundary:

- The #504 delivery itself (script-location skills resolution, the 19-false-CRITICAL cure, `--repo-root` flag parsing) — fixed by `c9b47ecf`, specified in `0175-us-504.spec.md`, regression-locked here only.
- The installer payload: whether a global install ships `bin/skill-dependencies.json` is owned by `bin/cli.js`, not by this checker.
- Install-scope classification and shared hub precedence: `resolve_consumer_root.cjs` and `ws-check-harness` `detect_install_mode.cjs` keep their semantics; this change may consume them, not redefine them.
- Every non-resolution check in the script (workflow simulation, step continuity, script syntax, state isolation, G2 and autoMode contracts).

## Implementation Decisions

### D1 — Reporting posture when the parity check cannot resolve its target (open gray area)

Two defensible postures; both keep the delivered mismatch detection intact.

| Option | Behavior | Cost |
|---|---|---|
| **A — explicit skip (chosen)** | Emit a `skipped` record naming the missing manifest path, keep the check visible in `--json` and the markdown report, and preserve exit 0 when nothing else is CRITICAL | Consumers must read the payload to notice the skip; a CI that greps only the exit code still sees green |
| **B — fail closed** | Treat an unevaluable parity check as a CRITICAL finding and exit 1 | The documented global-only layout (no `bin/` shipped) would fail for every consumer, converting a visibility defect into a false failure and re-creating the false-FAIL class that #504 removed |

Chosen default: **A**, with the fail-loud branch preserved where the missing input is a genuine defect (the resolved root is a package root carrying `bin/skill-dependencies.json` or `bin/cli.js`, yet one manifest is absent). Rationale: the parity invariant compares two package manifests, so a global install that ships neither side is *not applicable*, not *broken*; the reported defect is the silence, and a skip record removes the silence without inventing a false failure. Pinned by AC5, AC6, and AC7; the alternative stays available as a future opt-in (see Deferred Ideas).

Unresolved sub-question: whether AC8's degraded-resolution WARNING should also flip the overall status when a caller asks for strictness. Currently it does not; the overall status is driven by CRITICAL findings only, which is the existing contract.

### D2 — Resolver route (implementation decision, not a product choice)

| Option | Behavior | Cost |
|---|---|---|
| **A — reuse the shared precedence (chosen)** | Consume `resolve_consumer_root.cjs` (`resolveRepoRoot()`, `consumerHubExists()`, `inside()`) so explicit override, consumer hub or cwd, and fallback order come from one place | The script gains a cross-tree require from a shared runtime path, so a partial tree needs an explicit local fallback; the shared resolver also throws when the working directory *is* a global skills root, which changes a currently-silent case into a loud one |
| **B — repair the local heuristic in place** | Drop the install-parent candidate from `findRepoRoot()`, consult cwd before the ancestor scan, and make the no-marker branch reachable | Keeps the script dependency-free and the diff minimal, but leaves two repo-root heuristics in the codebase that can drift apart again |

Chosen default: **A**, with a local fallback when the shared module is unreachable, so a partial tree degrades instead of crashing. Rationale: repo-root resolution is a recorded anti-regression area and the shared module already single-sources the precedence used by the harness gates; the reference pattern for this failure class is to consume the shared contract rather than add a third heuristic. Both routes satisfy AC1 through AC13, because the ACs assert observable outcomes (resolved root, provenance, skip record) rather than a specific implementation; the pinned provenance vocabulary in AC1 is what keeps the two routes comparable in tests.

### D3 — Diagnostic shape

- Chosen: additive keys on the existing payload (resolved root, provenance, per-check status with reason). Existing consumers of `{status, issues, simulations}` keep working unchanged.
- Rejected: replacing the payload with a new top-level checks array keyed by check id. It would be cleaner long term but breaks every current reader for no requirement in this failure class.

### D4 — Consumer checkout detection

- Chosen: markers (`.git`, `.ws/config.json`, `package.json`) checked only at the working directory, with no parent walk.
- Rejected: walking up from cwd to find a marker. That is the same ancestor heuristic that produced the reported defect; it would choose an unrelated parent whenever the consumer directory itself lacks a marker.

## Deferred Ideas

- **Strict mode for skipped checks.** A `--strict` flag or a config key that turns any skipped repo-level check into a non-zero exit, for CI consumers that prefer fail-closed over visibility. Deferred: no consumer request yet, and it adds an exit-code branch to a gate whose documented contract is "exits 0 when nothing is CRITICAL".
- **Uniform per-check status across every repo-level check.** Extending the `checked` or `skipped` vocabulary from the parity check to all checks, so a vacuous pass is impossible anywhere in the report. Deferred to keep this change inside the reported failure class; the resolution fix already removes the vacuous-pass cause for the ancestor-heuristic case.
- **Installer-side manifest provisioning.** Shipping a parity manifest snapshot or a versioned hash inside global installs so parity could be meaningfully evaluated there instead of skipped. Deferred: installer-owned, and it changes the managed payload rather than the checker.
- **One shared repo-root resolver for all `ws-check-*` scripts.** Folding every sibling gate onto the shared precedence contract in a dedicated pass. Deferred: a cross-skill refactor well beyond this defect; this spec only reuses the shared contract where it already fits.
