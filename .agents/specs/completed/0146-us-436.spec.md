# Specification — features to be emphasized in website and detailed in wiki

## Description

This is a **documentation emphasis** task, not a code-behavior change. Four capability clusters already ship but are under-sold on the public site and under-detailed in the living wiki. The work adds prominent site feature surfaces for each cluster and expands the corresponding `{wikiDir}` pages so the detail is discoverable and verifiable.

Clusters to emphasize:

1. **Proof of work** — the optional post-completion UI-evidence collector gated by `defaults.enableOptionalProofOfWork` + `defaults.enableAutomaticEvidenceCollectForProofOfWork` with `defaults.projectRootFolderToSave` (default `{projectRoot}/.proofOfWork/{slug}`). The evidence folder is never committed.
2. **Translate to human** — the `ws-spec-translate-to-human` runbook companion (numbered Implementation / UI Test / Out of scope steps) beside an agent spec.
3. **Unattended workflows** — `autoMode` full-mode continuous orchestration (Steps 0→9 chained, mid-step checkpoint + turn-boundary pause resume) plus `ws-spec-multi` batch execution.
4. **Spec organizer, subfolder sync, and cleanup** — `ws-spec-organizer` status subfolders (`pending` / `completed` / `archived`), `ws-spec-index sync` after a move, and `ws-spec-archive` / `ws-cleanup` disposable-artifact cleanup.

Architecture touchpoints: the static site source/generator (`bin/build-site.js` and the marked feature blocks in `docs/index.html`), the human docs (`FEATURES.md`, `README.md`), and the living wiki under `{wikiDir}` (`index.wiki.md`, `delivery/spec-to-pr-pipeline.md`, `specs/spec-lifecycle.md`, `harness/diagnostics-and-benchmarks.md`, and any new page). Package version and integrity are in scope only if the release-PR rule requires a bump.

## Acceptance Criteria

### Website emphasis

- AC1: The site presents a visible feature block or card for each of the four clusters (proof of work; translate to human; unattended `autoMode` + `ws-spec-multi`; spec organizer/subfolder sync/cleanup) in the `#features` area.
- AC2: Each new feature surface carries a short factual description naming the real config keys, skill ids, or commands (no invented capability, no host-product coupling) and a link to its wiki page or anchor when one exists.
- AC3: The feature surfaces are generated or marker-delimited in the site source (`bin/build-site.js` and/or `<!-- ...:start -->` blocks in `docs/index.html`) so `node bin/build-site.js` reproduces them deterministically instead of losing them on rebuild.

### Wiki detail

- AC4: `{wikiDir}/delivery/spec-to-pr-pipeline.md` details the proof-of-work post-completion step (both switches, the folder setting, the never-committed rule) and the unattended `autoMode` chain (checkpoint + turn-boundary pause resume), matching shipped behavior.
- AC5: `{wikiDir}/specs/spec-lifecycle.md` details `ws-spec-translate-to-human` (runbook shape, non-blocking refinement hook) and the organizer/subfolder workflow (`resolve_spec_path.cjs` prefix ordering, `pending`/`completed`/`archived`, `ws-spec-index sync` after a move).
- AC6: `{wikiDir}/delivery/spec-to-pr-pipeline.md` details `ws-spec-multi` batch behavior (classify each spec, dispatch one pipeline at a time, isolated `workflowType`, no cross-resume), or a dedicated wiki page is added and cross-linked.
- AC7: Cleanup is detailed where it belongs (`{wikiDir}/harness/diagnostics-and-benchmarks.md` and/or `specs/spec-lifecycle.md`): `ws-spec-archive` harvests shipped plan folders into `index.PRD`; `ws-cleanup` lists disposable leftovers and deletes only user-approved untracked paths.
- AC8: Every new or edited wiki page keeps the required `## Feature` and `## How it works` headings (feature subpages) and passes `ws-wiki` link/heading validation with no broken links or unresolved anchors.

### Docs, harness, and integrity

- AC9: `FEATURES.md` and `README.md` reflect the emphasized clusters (at least a named entry per cluster) so the human docs and the site do not diverge.
- AC10: `ws-check-harness` Phases 0–5c report 0 findings, `test/test-harness-clean.js` reports 0 findings, and the wiki validator exits 0.
- AC11: If the change ships as a release PR, `package.json` `version` and `packageVersion` in `bin/skill-dependencies.json` are bumped once and `npm run generate-integrity` + `npm run verify-integrity` exit 0 (doc-only catalog fixes may instead rebuild the site without a bump per the ship rules).

## Validation & Observation Notes

### Telemetry & Observable Signals

- `node bin/build-site.js` exits 0 and the rebuilt `docs/index.html` contains a named surface for each cluster (proof of work, translate to human, unattended `autoMode` + `ws-spec-multi`, organizer/sync/cleanup).
- The wiki validator (`ws-wiki` validation script) exits 0 with no broken links or unresolved anchors across edited pages.
- `match` checks: `rg -n "enableOptionalProofOfWork|ws-spec-translate-to-human|autoMode|ws-spec-multi|ws-spec-organizer|ws-spec-index sync|ws-cleanup" docs/index.html` returns a hit per cluster.
- `npm run test` and `test/test-harness-clean.js` (0 findings) exit 0; `ws-check-harness` Phases 0–5c report 0 findings.
- When shipped as a release PR, `npm run verify-integrity` exits 0 after `npm run generate-integrity` and the site footer shows the bumped version.

### Negative & Failing Test Scenarios

- A feature surface added only by hand-editing `docs/index.html` without a generator/marker source: a rebuild (`node bin/build-site.js`) drops it; the reproducibility check fails until the surface is generated or marker-delimited.
- A wiki detail section linking to a renameable anchor that does not exist: `ws-wiki` link validation fails with the broken target named.
- A site claim naming a config key or skill id that is not shipped: the factual cross-check against `config.json.example` / skill ids fails and the claim must be corrected.
- `FEATURES.md`/`README.md` left unchanged while the site emphasizes new clusters: the docs-sync check flags the divergence.
- A feature page missing the required `## Feature` / `## How it works` headings: `ws-wiki` heading validation fails.
- Regenerating integrity without a version bump when the change is classified as a release change: the version/merge-base check fails before ship.
