# Context — US-288 packaging vs hub routing

## Feature Boundary

Issue 288 reports consumer `ws-check-harness` findings after a workflows install. Two product responses exist:

1. **Vendor** `ws-memo` and `ws-session-tracking` into this package (issue expected item 1 first option).
2. **Treat them as external companions** from the spec-memo package, align hub docs and the harness so missing local bodies are not phantom/critical (issue expected item 1 second option: document + fail-closed skip).

Chosen: option 2. This package already states runtime vault skills are not authored here. Vendoring would create a second SoT and violate the spec-memo bridge trap.

## Implementation Decisions

| Decision | Choice | Why |
|----------|--------|-----|
| Installer membership | Do not add ids to `packages.workflows` or `packages.extra` | Bodies are not in this repo’s `.agents/skills/` SoT |
| Always-applied | Remove unpackaged ids from the mandatory table; optional companion section | Generator `DEFAULT_ALWAYS_APPLIED` already omits them |
| CATALOG Layer rows | Do not add `.agents/skills/ws-memo` literals | Files do not exist in this SoT; Layer ↔ disk would still fail |
| Task router | Keep intents, mark load target as external / `{globalSkillsRoot}` | Agents still know where to look after `/ws-memo install_skills` |
| CATALOG scope note (consumer hub) | Same-folder `skill-dependencies.json` | Consumer trees have no `bin/` |
| Harness | Intentional omission for declared `externalSkills` | Stops agent walk treating task-router ids as phantoms |
| `installed-skills.json` | Do not track foreign skill trees | Installer must not prune spec-memo-installed folders as unmanaged extras; do not add fake membership |

## Deferred Ideas

- Installer copying spec-memo skills (belongs in spec-memo `install_skills`).
- Layer 5 rows with fake SoT paths (rejected).
