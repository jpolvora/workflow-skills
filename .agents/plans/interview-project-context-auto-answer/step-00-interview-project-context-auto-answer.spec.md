# Specification — ws-interview: project-context grounded auto-resolution

## Description

Strengthen `ws-interview` (SoT: `src/skills/ws-interview/SKILL.md`) so that when resolving plan gaps / auto-answering interview questions, the agent **must** exhaust **project-level evidence** before inventing or escalating.

Today the skill already requires “diligent exploration” (codebase, ADRs, schema, `MEMORY.md`, specs) and escalate remaining blocking gaps via `user-gate` / `needs_user`. That guidance is incomplete relative to the intended behavior:

1. **Mandatory project-context sweep** — before asking the user or applying an ungrounded default, search all relevant in-repo sources for the best answer: other specs (`{specsDir}`, `{plansDir}/**/step-00-*.spec.md`), `{sharedDir}/MEMORY.md` (+ `memory/*` when present), codebase and established design patterns, architecture docs / standards (`domain.architectureSpec`, `domain.glossaryFile`, stack companion, ADRs), and project rules / guides (`config.json` → `rules.*`, hub `AGENTS.md`, packaged standards skills when configured).
2. **Evidence-backed resolution** — when a project source answers the gap, record the resolution and cite the evidence in the interview registry (path + brief rationale). Prefer project evidence over model preference when they conflict.
3. **Fallback by mode** — only after the project-context sweep fails to yield a confident answer:
   - **`autoMode` (or equivalent auto-answer path):** apply the agent’s best technical judgment (sensible default), mark the registry entry as model-inferred (not project-sourced), and continue without blocking on the user.
   - **Non-auto (interactive):** escalate surgically via `user-gate` / `needs_user` per existing Grilling Protocol (one question per round, recommended option first, escalation cap unchanged).

Scope is skill-prose / protocol clarity in `ws-interview` (and any minimal cross-links from orch/gates if needed for autoMode wording). No new scripts or UI required unless implementation discovers a hard gap.

## Acceptance Criteria

- AC1: `src/skills/ws-interview/SKILL.md` documents a mandatory **project-context sweep** before user escalation or ungrounded defaults, covering at least: related specs, `{sharedDir}/MEMORY.md` (and `memory/*` when present), codebase / design patterns, architecture standards / ADRs / domain docs from config, and project rules / guides (`rules.*`, hub instructions).
- AC2: The Resolve step requires preferring an answer grounded in project evidence over model preference when both exist, and requires appending resolution evidence (source path(s) + short rationale) to the gap registry entry.
- AC3: When the project-context sweep does **not** yield a confident answer and the run is in **`autoMode`** (workflow auto-answer), the skill requires the agent to apply best judgment / sensible default, mark the resolution as model-inferred, and **not** block on `user-gate` for that gap (subject to existing hard-stop / escalation-cap rules elsewhere in the orch).
- AC4: When the project-context sweep does **not** yield a confident answer and the run is **not** auto, remaining **blocking** gaps escalate via existing Grilling Protocol (`user-gate` / `needs_user`, one question per round, recommended choice first, max 3 rounds then defaults).
- AC5: Non-blocking gaps remain auto-resolvable via defaults after the sweep (project-sourced when found; otherwise defaults), without requiring user escalation.
- AC6: Dogfood / harness copy under `.agents/skills/ws-interview/` stays aligned with SoT after the SoT edit (or is regenerated by the usual promote/copy path used in this repo).
- AC7: Language remains **en-us**; skill stays harness-neutral (no IDE/agent product names; use `user-gate`, `{sharedDir}`, `{specsDir}`, `{plansDir}` tokens).

## Notes

- **Baseline gap:** Current Grilling Protocol items 1 and Resolve already mention codebase / ADRs / schema / `MEMORY.md` / specs, but do not enumerate the full source set, do not require evidence citations in the registry, and do not branch fallback by `autoMode` vs interactive.
- **Out of scope:** Changing lite pipeline (lite has no interview step); changing escalation cap defaults; inventing new config keys unless implementation proves one is necessary; rewriting orch FSM beyond a one-line cross-reference if autoMode semantics need clarifying in `gates.md` / STEP-DISPATCH.
