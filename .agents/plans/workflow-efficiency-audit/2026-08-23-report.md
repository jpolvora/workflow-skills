# ws-spec-to-pr efficiency audit

**Date:** 2026-08-23  
**Method:** ws-fable-method (evidence → decide → act)  
**Baseline spec:** `harness-efficiency-and-verifiability.spec.md` (marked done in index.PRD; dispatch wiring still incomplete)

This report enumerates the standard pipeline, names token/time sinks that do **not** raise the verify score, and records helper-script failures. Quality gates stay fail-closed.

## What already shipped (do not redo)

W1 context budget is largely real:

- Subagent preamble is `## Subagent contract` + injected MEMORY slice (≤ 4 KB), not six full skills.
- `measure_harness.cjs` models ~97% harness-byte reduction vs the 962,298 B hermes baseline.
- Score is derived from `ac-ledger.json` (`ac_ledger.cjs score`); agents cannot author it.
- Fix-PR exits without the 330 s heartbeat when a fresh read is clean.
- Node `update_state.cjs` / `validate_state.cjs` are the live recipes.

The modeled artifact-reread metric is **optimistic**: default `measure_harness` reports 0 B because `plan.index.json` is still off the live dispatch path.

**Post-mutating every step:** `update_state` dispatch/finish + JSONL + `run.json` + plans `index.json` + checkpoint tag + `validate_state --pre-advance` + Progress Board + user-gate. That is the FSM spine. Do not remove it. Default `gateGranularity: step` is ~10 blocking gates; `phase` cuts to 5 without dropping score logic.

## Approaches considered

1. **Wire existing scripts into dispatch (chosen).** Lowest risk. Matches already-approved ACs 13, 15–16, 19, 31, 45. Fixes validator/recipe drift. Does not weaken score ≥ 9.
2. **Rewrite remaining Python now.** That is `unique-skill-script-runtime.spec.md` (open). Large, separate PR. Do not mix with dispatch wiring.
3. **Default `gateGranularity: phase` and `parallelVerifyReview: true`.** Speed only. Changes human checkpoints and review isolation. Leave defaults; document opt-in.
