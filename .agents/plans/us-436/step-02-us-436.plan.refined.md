## 0. Summary & Business Rules

The four capability clusters below already ship. This change is **documentation emphasis only**: it (a) adds a prominent, deterministically generated feature surface per cluster to the public site `#features` grid, and (b) tightens the living wiki so each cluster is discoverable and verifiable. No runtime behavior changes.

Clusters:
1. **Proof of work** — optional post-completion UI-evidence collector. Gated by `defaults.enableOptionalProofOfWork` (explicit `true` only) + `defaults.enableAutomaticEvidenceCollectForProofOfWork`; folder from `defaults.projectRootFolderToSave` (default `{projectRoot}/.proofOfWork/{slug}`); evidence folder is never committed.
2. **Translate to human** — `ws-spec-translate-to-human` runbook companion (numbered Implementation / UI Test / Out of scope steps) beside an agent spec; non-blocking refinement hook.
3. **Unattended workflows** — `autoMode` full-mode continuous orchestration (Steps 0→9 chained; host-forced mid-step turn end uses `checkpoint` / `pause-turn` resume) plus `ws-spec-multi` batch execution.
4. **Spec organizer, subfolder sync, and cleanup** — `ws-spec-organizer` status subfolders (`pending` / `completed` / `archived`), `ws-spec-index sync` after a move, and `ws-spec-archive` / `ws-cleanup` disposable-artifact cleanup.

Business rules: no invented capability; no host-product coupling; deterministic site generation via the marker block; reuse existing wiki pages; en-us only.
