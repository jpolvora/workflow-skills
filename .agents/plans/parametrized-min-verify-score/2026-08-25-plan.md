# Parametrized min verify score Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the hardcoded Step 5 Advance bar of 9 with `defaults.minVerifyScore` (integer 1–10, omitted/invalid → 9) and add a low-effort Reach-10 `user-gate` after verify.

**Architecture:** One exported resolver on `resolve_consumer_root.cjs` is the runtime SoT. `workflow_state.cjs`, `merge_verify_review.cjs`, and `classify.cjs` call it. Gate/orch/docs name the config key instead of a literal 9. Ledger scoring caps in `ac_ledger.cjs` stay unchanged.

**Tech Stack:** Node 22, `config.schema.json`, hub docs, `npm run test`.

**Spec:** `.agents/specs/parametrized-min-verify-score.spec.md` (AC1–AC13, authoring PASS).

## Global Constraints

- Language: en-us for skill bodies, gates, banners, harness docs.
- Edit SoT only under `$PWD/.agents/skills/ws-*`. Never write `{globalSkillsRoot}`.
- `ws-shared/AGENTS.md` stays under 14000 UTF-8 bytes (`node test/test-context-budget.js`).
- Do not change `ac_ledger.cjs` score formula (`knownDefect` cap 8, `missingEvidence` cap 9, `completeTen` path to 10).
- Do not add a second min-score knob.
- Runtime omitted/invalid `minVerifyScore` → 9 (schema `default` is seed/docs only).
- Single package version bump at the end (`npm run build-site:bump`).
- Do not commit unless the user asked for a commit.

```js
function resolveMinVerifyScore(config) {
  const n = config?.defaults?.minVerifyScore;
  if (typeof n !== 'number' || !Number.isInteger(n) || n < 1 || n > 10) return 9;
  return n;
}
```
